# Part 2: lint and VoxGarbler Python CI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** VoxGarbler runs its Python tests in CI, and portfolio, VoxGarbler and flashback-sampler each lint every commit locally and in CI from one `.pre-commit-config.yaml`, with zero findings at merge.

**Architecture:** Each repo gets one hook config that prek runs in two places: the local commit hook and a CI `lint` job that calls `check.yml` v1.0.0 with `prek run --all-files`. Each repo's fix pass lands as separate format, autofix and manual commits so blame can skip the mechanical ones. VoxGarbler first gets `py-ci.yml` so its lint fix PR is tested.

**Tech Stack:** prek 0.5.5, ruff 0.17.1 (via `astral-sh/ruff-pre-commit`), oxlint 1.88.0 (via `oxc-project/mirrors-oxlint`), zig 0.16.0, GitHub Actions through `Phlares/workflows` `check.yml` v1.0.0, Dependabot `pre-commit` ecosystem, uv, pytest, vitest.

## Review Focus

1. **A branch with no hook config blocks every commit.** The owner's VoxCollage checkout sits on a feature branch, and old worktrees exist in all three repos. Plain `prek install` makes `git commit` exit 1 there ("No `prek.toml` or `.pre-commit-config.yaml` found"; verified 2026-10-16, prek 0.5.5). `prek install --allow-missing-config` lets those commits through and still blocks on a failing hook (verified). Every owner-step line in this plan uses that flag. Pinned by Task 2 Step 13.
2. **`ruff-format` also rewrites Markdown.** The v0.17.1 hook matches `types_or: [python, pyi, jupyter, markdown]`, and ruff 0.17.1 reformats Python blocks inside `.md` files (verified). The spec measured `.py` files only, so the hook entry sets `types_or: [python, pyi, jupyter]`. Pinned by the "no `.md` in commit 1" check in Tasks 2 and 3.
3. **Squash or rebase merges break `.git-blame-ignore-revs`.** The file lists branch commit hashes. flashback and VoxGarbler merge with merge commits (checked: #92, #100, #70), so the hashes reach the default branch. Portfolio merges through Trunk, which squashes (#636 has one parent). Portfolio therefore lands its autofix as its own PR first (Task 4). A rebase of a fix branch after the blame file is written also breaks it: update fix branches by merging the base in, never by rebasing. Pinned by the `merge-base --is-ancestor` check after each merge.
4. **A hook that rewrites a file but exits 0 must still fail CI.** `ruff format` and `zig fmt` exit 0 after fixing. prek must report the change as a failure. Pinned by the format-only mutation commit in Tasks 2 and 3 (CI `lint` red, `report.json` step `run`).
5. **The `zig fmt` check is lost in the move.** The `zig` job drops `zig fmt --check build.zig src`. If the hook's `files:` regex misses a file, nothing checks it. `core/build.zig` and `core/src/**` are the only `.zig` files on `dev` (checked); the regex `^core/.*\.zig$` covers both. Pinned by the zig mutation in Task 2 Step 11.

## Shared procedures

Every task below calls these by name. They are written out once here because they are long; each task step states the inputs.

**P1. Worktree.** Inputs: `<repo>` (local folder name), `<base>` (default branch), `<branch>`.
```bash

cd /c/Users/Ryon/Documents/dev/<repo> && git fetch origin
git worktree add "$S/wt-<repo>-<branch-slug>" -b <branch> origin/<base>

```

**P2. Python test env (uv, per worktree).** An editable install from the owner's main checkout would shadow the worktree's package, so each worktree gets its own venv. Inputs: `<install>`.
```bash

source .venv-ci/Scripts/activate

```
Keep it out of `git status`: `echo .venv-ci/ >> "$(git rev-parse --git-common-dir)/info/exclude"`.

**P3. Fix-pass commits.** Inputs: `<suite>` (the test command), `<baseline>` (counts from the base branch).

Commits 0, 1 and 2 hold known findings on purpose. If a prek hook is already installed in the repo's main checkout (linked worktrees share it), it would block them. So every commit command in P3 and P5 runs with `SKIP=ruff-check,ruff-format,oxlint,zig-fmt` in front (prek's documented skip list; harmless when no hook is installed). Commit 3 and later run without it.
1. Commit 1, format: `prek run ruff-format --all-files` (exit 1 is expected: it reformatted). Check `git diff --name-only -- '*.md'` prints nothing. `git add -u && SKIP=ruff-check,ruff-format,oxlint,zig-fmt git commit -m "style: ruff format"`. Run `<suite>`; counts must equal `<baseline>`.
2. Commit 2, autofix: `prek run ruff-check --all-files` (the hook carries `--fix`; ruff applies safe fixes only). For repos with oxlint, also `npx --yes oxlint@1.88.0 --deny-warnings --fix <oxlint paths>`. `git add -u && SKIP=ruff-check,ruff-format,oxlint,zig-fmt git commit -m "style: lint autofixes (ruff --fix, oxlint --fix)"`. Run `<suite>`; equal counts.
3. Commit 3, manual: loop `prek run --all-files` and fix the reported findings by hand until it exits 0 (fix guide P4). `git add -u && git commit -m "fix: resolve remaining lint findings"`. Run `<suite>`; equal counts.
4. Commit 4, blame file:
   ```bash
   { echo "# Mechanical lint commits. Use: git config blame.ignoreRevsFile .git-blame-ignore-revs"
     git log --format='%H # %s' -n 1 --grep '^style: ruff format'
     git log --format='%H # %s' -n 1 --grep '^style: lint autofixes' ; } > .git-blame-ignore-revs
   git add .git-blame-ignore-revs && git commit -m "chore: blame ignores the mechanical lint commits"
   ```
   A commit with no changes (for example no autofixes) is skipped, and its line is left out.
From commit 4 on, never rebase this branch. To pick up a newer base, `git merge origin/<base>`, then rerun `prek run --all-files`.

**P4. Manual fix guide.** Fix the code; never weaken the rule set.
- **F401** unused import: delete it. In an `__init__.py` re-export, add the name to `__all__`.
- **F841** unused local: delete the assignment if the right side has no side effect. If it does (a call), keep the call and drop the name.
- **F811** redefinition: delete the earlier definition or import. Read both first; the later one wins at runtime, so keep the later.
- **F632** `is` with a literal: change to `==` / `!=`. This changes behaviour (that is the bug); add a test that pins the corrected comparison if none exists.
- **E722** bare `except:`: `except Exception:`. Keep `BaseException` only where the code re-raises.
- **E402** import not at top: move it up. Where a `sys.path` change must come first (scripts), keep the order and add `# noqa: E402` on that line.
- **E741** ambiguous name `l`/`O`/`I`: rename.
- **B006** mutable default: `def f(x=None):` + `if x is None: x = []`.
- **B007** unused loop variable: rename to `_` or `_name`.
- **B008** call in a default (non-FastAPI): hoist to a module constant, or the `None` pattern.
- **B904** `raise` inside `except` without `from`: `raise X(...) from err` (or `from None` when the cause is noise).
- **B905** `zip()` without `strict=`: add `strict=True` where both sides must match in length, `strict=False` otherwise. Read the call before choosing.
- **UP** findings left after autofix: apply the suggested syntax; `requires-python` already limits them.
- oxlint **no-unused-vars**: delete; for intentionally unused parameters, prefix `_`.
- oxlint **no-useless-escape**, **no-empty**, **no-constant-condition**: fix the code; an intentional empty `catch` gets a comment inside the block.
- Anything not listed: read the rule doc (`ruff rule <CODE>`, or the oxlint rule page) and fix it.

`# noqa: <CODE>` (ruff) or `// oxlint-disable-next-line <rule>` (oxlint) is allowed only when the code is right and the rule is wrong for that line, with a reason in the same comment. Each one is listed in the PR body with its reason. More than 10 in one repo: stop and ask the owner.

**P5. Mutation check in CI.** Inputs: a one-line change that breaks only formatting.
```bash

SKIP=ruff-check,ruff-format,oxlint,zig-fmt git commit -am "test: mutation, <what> (reverted next)" && git push
```

Expected: `run`. Then `git revert --no-edit HEAD && git push`; lint green again. Record `mutation: <what> → lint red` in the ledger and the PR body.
